# 从排版到自己的公众号｜按实际能力选择

**不用先连接公众号，才能使用风格包。** 排好之后由用户决定是否继续。AI 每次只引导当前必要的一步，不把下面技术项一次丢给用户。

## A. 手动放入后台（不需要 AI 连接器）
1. 用户自己在浏览器登录微信公众平台，核对公众号名称；没有账号也可保存本地结果，不要求开通。
2. 后台新建图文草稿。打开本篇 article-preview.html，复制浏览器中可见排版内容，尝试粘贴到正文区。**不要把 HTML 源码直接当正文粘贴**。工具若有复制富文本功能可使用，本包不假装已带此按钮。
3. 核对文字、图片、重点和间距。内嵌图片/样式可能无法保留：使用用户原图在后台重新上传到对应位置，准备并选择封面。图片未显示不能当已交付。
4. 保存草稿，用后台预览功能发送到自己的微信，手机检查。明显差异由 AI 标出并询问是否接受兼容调整，不偷偷换风格。
5. 用户认可后自行决定是否发布，本包不自动发布。

这是无需连接器的备选路，不是保证 HTML 无损粘贴的承诺。

## B. 想让 AI 存草稿：先问一个问题
> 你现在用的 AI 或工作平台里，有没有已经连接好的公众号工具？不确定的话，我先检查可用工具；没有也可以选手动操作，或配置你自己的连接方式。

AI 查工具清单/说明，确认真实存在的“上传正文图片、永久封面素材、新增草稿、读回草稿”能力和适配范围。不要虚构插件、安装卡片或已完成授权。工具名带“微信”不等于支持本包。

### B1. 已有连接器，或提供公众号授权的第三方平台
1. 说明工具提供方、目标账号、需要哪些权限和费用（未知先查），用户决定是否连接。
2. 用户本人通过平台真实公众号授权流程操作，核对授权页面、账号、权限。不在对话发送密码、AppSecret、登录二维码会话或 Cookie。
3. 获准后做最小能力/账号检查；只读权限不等于新增草稿权限。第三方授权、AI工具权限与公众号接口权限都需满足。
4. 若缺“直接消费本包正文”的能力，说明缺适配，不用其内置模板重排蒙混过关。可改走 A；不能说安装后一定能推。

### B2. 没有连接器，但用户愿意配置自己的服务端
可选开发路线，不是第一次排版必做项。本包没有附带已验证真实上传器。

1. 用户在自己的公众号后台查看开发接口及实际权限，确认素材和草稿能力。菜单随版本/账号变化，以当前界面为准；不能只凭“有账号”保证可调用。
2. 确认已有后端还是新建适配服务，优先复用已有系统，避免重复取令牌干扰服务。不为建草稿就要求启用/更改消息回调 Server URL 或停用原系统。
3. 开发者把 AppSecret 等放服务端安全配置或受保护凭据存储，不放浏览器前端、聊天、包、版本库或日志。AI 仅报告就绪状态，不回显密钥。
4. 按账号当前接口要求配置实际出口公网 IP 白名单（如需要），不是 127.0.0.1 或猜测内网 IP；用户/管理员在后台操作。token 获取、缓存、更新由服务端负责。
5. 实现并检查 C 适配合同；用户允许连接检查后确认账号与能力。缺权限/配置不通则说明卡点并提供 A，不反复让用户交密钥。

## C. 所有 AI / 连接器共用的草稿交接合同
输入：已确认的 article-fragment.html + render-report.json + 原配置标识/实际配置哈希 + 确认的标题、作者/摘要（如有）、封面、目标账号。

上传前确认：
> 将「文章标题」和这张封面存到「公众号名称」的草稿箱，不发布，也不覆盖旧稿，可以吗？

连接授权不等于本篇上传授权。明确同意当前账号与版本后才执行素材上传与草稿创建。

1. 验证 fragment 与 report 哈希一致，非 calibration-only；凭据与权限就绪。保留不可变上传快照。
2. 提取正文/导语/二维码实际内嵌图片，通过官方“上传图文消息图片”接口 `/cgi-bin/media/uploadimg` 获得 URL 并替换 img src；封面上传永久素材取得 thumb_media_id。data URL 或外站图片不能原封交给草稿接口。
3. 只做素材 URL 等接口必需转换，不重排、压扁成长图或换连接器默认配色。保留上传前后正文哈希与差异；若需改版式先确认。
4. 经 `/cgi-bin/draft/add` 新建图文草稿，保存真实 media_id；通过草稿详情接口读回核对标题、正文、封面。不得调用发布/群发接口。
5. 给用户草稿标识及“到公众号后台草稿箱打开”的指引，带其手机预览检查样式与二维码。回读通过不代替手机验收。

失败：只记录脱敏错误码与阶段。超时先核是否已创建，不盲目重试导致重复。素材上传但草稿失败如实报告，不自动删其他素材/旧稿。无真实返回不能用 mock media_id 充数。
